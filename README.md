# diffnote

git の差分やディレクトリに、ローカルでコメントを書き、レビューを 1 つのファイル(`.diffnote`)で共有するコマンドラインツールです。サーバーは要りません。

## インストール

必要な Rust は 1.88 以上です(`Cargo.toml` の `rust-version`)。

```sh
cargo install --path .
```

ビルド済みの実行ファイル(Linux x86_64 の静的版、Windows x86_64、macOS Apple Silicon)は、GitHub の Releases から取れます。`SHA256SUMS` で、ダウンロードしたファイルを確かめられます。

## 使い方

```sh
# ベース(例: main)から、ブランチの先端までをレビューする(コメントを書くと .diffnote ができる)
diffnote edit --base main feature

# 最後のコミット 1 つの変更をレビューする
diffnote edit HEAD

# 書いたコメントを一覧する
diffnote show

# 誰でも開ける HTML に書き出す
diffnote export review.html
```

- `edit` は差分を `$EDITOR` で開きます。コメントを書いて保存すると、バンドルに追記されます。もう一度 `edit` すれば、既存のコメントが表示され、返信や解決もできます。
- `edit` は、**ベース**から**比較対象**までの差分をレビューします。比較対象は 1 つだけ指定します(範囲の `A..B` は指定できません)。ベースは、`init` で決めるか、まだバンドルがないときに `--base` で決めます(`edit --base A B` は、`init A` してから `edit B` するのと同じ意味です)。ベースも `--base` もなければ、そのコミットの親がベースになります(コミット 1 つの変更のレビュー)。マージベースから始めたいときは、`--base $(git merge-base main feature)` と書きます。コミット済みの内容だけが対象です。
- バンドルができたあと、ベースは変えられません(同じベースを `--base` で言い直すのはかまいません)。`edit` を重ねると、ベースは同じままで、比較対象だけが進んだリビジョンが増えます。
- `-f FILE` でバンドルのパスを変えられます(省略時は `./.diffnote`)。
- `--title "…"` でレビューにタイトルを付けられます(省略可。`init` にも指定できます)。エクスポートの見出しとページのタイトルに使われ、なければ「diffnote レビュー」です。後から変えるときも `edit --title`、取り消すときは `--title ""` です。
- コメントの作者名は、`--author "名前"`、なければ git の `user.name`、なければ `user.email`、なければ環境のユーザー名です(`--author` はそのときの `edit`/`init` にだけ効き、記憶されません)。
- エクスポートのトップバーには、差分の表示を「**統合**」と「**横並び**」(左が変更前、右が変更後)に切り替えるボタンがあります(選択はブラウザに保存されます。まだ選んでいないときは、開いたときの画面の幅が 1200px 以上なら横並び、それより狭ければ統合で始まります。開いたあとに画面の大きさを変えても、表示は変わりません。ただし、幅が 900px 未満のときは、横並びでも統合で表示されます)。エクスポートの HTML は、ブラウザ上の JavaScript で描画されるので、JavaScript が有効なブラウザが必要です(ファイルとして開けます。通信はしません)。
- エクスポートと `serve` の画面のトップバーに、「**解決済みを隠す**」のチェックがあります(解決済みのスレッドがあるときに出ます。`serve` では常に出ます)。**既定でオン**で、解決済みのスレッドのカードと、一覧の項目と、それだけに付いていた行の印が隠れます(チェックを外すと表示されます)。外した設定は、ブラウザに保存されます。
- 削除した行と、それに代わる追加した行(上から同じ順番の行同士)では、**変わった単語**が濃く強調されます(単語は、英数字と `_` の連なり、空白、記号 1 文字ずつで区切ります)。ほとんど似ていない行同士や、行全体が変わった場合、2000 文字を超える行は、強調しません。
- 差分が省略している行(ハンクの間、最初のハンクの前、最後のハンクのあと)は、「N 行省略」の行から**展開**できます。「↓ 20 行」でひとつ上のハンクの続きを、「↑ 20 行」で次のハンクの手前を、20 行ずつ表示します。「N 行をすべて表示」で、残りを一度に表示します。表示した行にも、`serve` ならコメントできます。`serve` の画面では、必要になったとき、サーバーから読み込みます。
- エクスポートした HTML でも展開できるように、省略行を HTML に埋め込めます(`--expand-limit 行数`、既定は 5000。全ファイル・全リビジョンの合計で、短い場所から順に埋め込みます。`0` で埋め込まず、`all` で全部埋め込みます)。上限を超えて埋め込まれなかった場所は、「N 行省略(この HTML には含まれていません)」と表示されます。埋め込めるのは、バンドルにファイルの全文が保存されている場所だけです。
- エクスポートの左側には、ファイルの一覧と、スレッドの一覧(場所と冒頭、解決済みかどうか)が出ます。スレッドを押すと、そのカードに移動して範囲が強調されます。ファイルの見出しとスレッドには「コピー」ボタンがあり、パス(`src/a.rs`)や、パスと行(`src/a.rs:10-13`)がコピーできます。行の形式は `edit --show` にそのまま使えます。
- エクスポートでは、各コメントの作者の横に、書いた日時が小さく薄い文字で出ます(見ているブラウザの時刻になり、マウスを乗せると詳細が出ます)。
- 共有は `.diffnote` ファイルを渡すだけです。受け取った人は `show`/`export`/`edit` で開けます。

### ブラウザで操作する(試験的)

```sh
diffnote serve            # ./.diffnote をブラウザで開く
```

自分のパソコンからだけ接続できる小さなサーバーが起動して、ブラウザが開きます。エクスポートと同じ画面で、次のことができます(画面全体は読み込み直されず、変わった部分だけが更新されます)。

- **新しい行へのコメント**: 行番号を押す(1 行)、行番号をドラッグする、Shift+クリックで範囲を広げる。選んだ行の下に入力欄が開きます(`Ctrl+Enter` で送信、`Esc` で取り消し。選び直しても書きかけは残ります)。
  **横並び表示**では、行番号を押した側(左が変更前、右が変更後)の行だけが選ばれます(ドラッグと Shift+クリックも同じ側の中で伸びます)。変更のない行は、どちら側を押しても両側の行として記録されます。表示を切り替えると、選択は解除されます。
- **ファイルへのコメント**: ファイルの見出しの「コメント」ボタン(折りたたまれていれば開きます)。**レビュー全体へのコメント**: 画面上部の「レビュー全体にコメントする」ボタン。
- **差分に出ていないファイルへのコメント**: 左のサイドバーの一番下にある、折りたたまれた「その他のファイル」を開くと、バンドルに保存されているファイルのツリーが出ます(ディレクトリは、開いたときに読み込みます。上の検索欄でも絞れます)。ファイルを押すと、その場に、全文が(長いものは 500 行ずつ、「続きを表示」で)表示されます。あとは、通常のファイルと同じ操作で、行やファイルにコメントできます。開いただけでは、何も記録されません。コメントを付けたときに、そのファイルの版が記録されます。「閉じる」で、表示を消せます。
  ディレクトリのレビューでは、保存されている全ファイルが選べます。**git のレビュー**では、バンドルに保存されていないファイルも、レビューを作ったリポジトリのコミットから開けます(`diffnote serve` を、そのリポジトリの中で起動するか、`--repo DIR` で場所を指定してください)。読むのは、記録されたコミットの内容だけで、作業ディレクトリの未コミットの変更は見えません。2 MB を超えるファイルとバイナリは開けません。コメントを付けると、そのファイルの版と内容が、バンドルに保存されます(開いただけでは保存されません)。リポジトリがない環境では、保存済みのファイルだけです(起動時に注意が出ます)。
- 各スレッドへの返信、解決にする、再開する。
- **編集と削除**: `serve` を起動してから、ここで追加したコメント(新しいスレッドと返信)には、「編集」と「削除」のボタンが付きます。スレッドの最初のコメントを削除すると、スレッド全体(返信と解決の記録も)が消えます(ほかで付いた返信があるときは削除できません)。編集も削除も、バンドルの記録そのものを書き換えます。`serve` を終了すると、そこまでのコメントは確定し、次に起動した `serve` からは編集も削除もできません(以前のコメントは対象外です)。
- **エクスポート**: トップバーの「エクスポート」ボタンで、今の内容を `diffnote export` と同じ HTML としてダウンロードできます(ファイル名はバンドル名に `.html`)。

別のタブや `edit` でレビューが変わっていた場合は、画面に戻ったとき(または、古い画面から操作したとき)に、最新の内容が読み込み直されます。

「終了」を押すと、ブラウザの画面とターミナルの両方に、今回の変更のおおよその内容(追加したスレッドと返信、解決、編集、削除の件数)と、保存先、いまのスレッドとコメントの数が表示されます。

URL には、起動ごとの使い捨てのトークンが付いています。終了はブラウザの「終了」ボタンか、ターミナルの Ctrl+C です。

まだできないこと: レビューの新規作成(いまは `init` / `edit` で作ります)、以前のコメントの編集と削除。

### 最初のバンドルを作る(`init`)

`init` は、最初のレビューバンドルを作るコマンドです。`.git` のあるリポジトリの中か、そうでないかで、動きが決まります。

```sh
# git のリポジトリの中: 指定したコミット(省略時は HEAD)を基準にする
diffnote init             # HEAD を基準にする
diffnote init main        # ブランチ名、タグ、コミット ID も指定できる
# …コミットを重ねる…
diffnote edit             # 基準から今の HEAD までの変更をレビューする

# git を使わないディレクトリ: ディレクトリ(省略時は `.`)の今の状態を基準にする
diffnote init             # 今の状態を保存する
# …ファイルを変更する…
diffnote edit             # 保存した状態(ベース)からの変更をレビューする

# 2 つのディレクトリを比べる(編集前と編集後)
diffnote edit --base old_dir new_dir    # old_dir をベースにして、new_dir までをレビューする
```

- **git のリポジトリの中:** コミットの ID だけが記録されます(中身は git が持っています)。`edit`(引数なし)は、ベースから今の HEAD までの変更をレビューします。HEAD が動いていなければ、同じリビジョンをもう一度開きます(返信や解決を足すためです)。`edit feature` のように、比較対象のコミットを指定することもできます。指定したコミットがなければ、何も作らずにエラーになります。
- **git のリポジトリの外:** ディレクトリの全ファイルが保存されます。`.diffnoteignore`(なければ `.gitignore`)に一致するファイルは含まれません。`edit`(引数なし、または `edit DIR`)は、**ベース(最初のスナップショット)**と、今のディレクトリを比べます。`edit` を重ねても、比べる相手はいつもベースです(前回からの差分ではありません)。
- **リポジトリの中でファイルのスナップショットを作る:** `diffnote init --files [DIR]` です。`edit --files --base OLD NEW` のように、`edit` と `serve` にも `--files` を付けられます。
- **`edit --base DIR`(ディレクトリ):** まだバンドルがないときに、`init DIR` してから `edit` するのと同じ意味になります。何もレビューするものがなければ、ベースだけのバンドルは残りません。バンドルがあるときは、ベースと同じ内容のディレクトリしか指定できません。
- すでにバンドルがあるパスには作れません。
- **リポジトリを指定する(`--repo DIR`):** `init`、`edit`、`serve` の `--repo DIR` で、どこからでも、そのリポジトリを対象にできます(コミットの解決とファイルの読み出しに使います。省略時は、実行したディレクトリのリポジトリ)。リポジトリでないディレクトリは、エラーになります。
### `serve` で、差分をブラウザでレビューする

`serve` は `edit` のブラウザ版で、指定のしかたも同じです。指定した差分は、リビジョンとしてバンドルに記録されて、そのままブラウザでレビューできます。

```sh
diffnote serve                    # git のバンドル: ベースから今の HEAD まで
diffnote serve feature            # 比較対象を指定する(`edit` と同じ)
diffnote serve --base main feature  # バンドルがなければ、ここで作る
diffnote serve .                  # ディレクトリのバンドル: `.` を、ベースのスナップショットと比べる
diffnote serve --files --base old_dir new_dir   # 2 つのディレクトリを比べる
```

- すでに記録された差分と、空の差分は、加えません。同じ指定で続けて起動しても、リビジョンは増えません。
- 指定が間違っていれば、何も加えずにエラーで終わります。
- ディレクトリのバンドルは、ディレクトリを指定したときだけ、差分を取り込みます(引数なしのときは、どのディレクトリか分からないためです)。
- 基準のあとにまだコミットがないときは、その旨が表示されます。
- `--repo DIR` を付けると、そのリポジトリを見ます。起動したあとに増えたコミットは反映されません(起動し直してください)。

### 差分に出ていない行へのコメント

```sh
diffnote edit --show src/main.rs            # ファイル全体
diffnote edit --show src/main.rs:40-60      # 行の範囲(`:40` なら 1 行)
```

## コメントの書き方

行頭が `>` の行がコメントです。それ以外は差分そのものなので、書き換えないでください。

```diff
 fn main() {
-    old();
+    new();
> この呼び出しは非同期にしたほうがよさそうです
>
> 理由: …
```

| 書き方 | 意味 |
|---|---|
| `>` 本文 | 直前の行へのコメント。連続する `>` は 1 つのコメントになり、`>` だけの行は段落の区切りになる |
| 空行 | コメントの終わり。続けて `>` を書くと別のコメントになる |
| `>>` 本文 | 直前のスレッドへの返信 |
| `>!resolve` / `>>!resolve` | スレッドを解決済みにする(`reopen` で戻す) |
| `>[` … `>]` | 範囲へのコメント。対象の行を `>[` と `>]` で挟み、`>]` の直後にコメントを書く(`>[名前` … `>]名前` で名前付き、ハンク越しも可) |
| `>!reanchor <id>` | 既存のスレッドを、この位置へ付け替える |
| `\` | 直後の 1 文字をそのまま書く(例: 行頭の `\>`) |

`edit` で既存のコメントを開くと、読み取り専用の `>#@<id> …` ブロックで表示されます。複数行にわたるコメントは、対象の範囲が `>#[<id>` と `>#]<id>` で挟まれ、その直後に `>#@ 作者 日時` のブロック(返信があれば続けて並ぶ)が来ます。1 行だけのコメントは、最初の `>#@<id> 作者 日時` にだけ id が付きます。スレッドの id は、`>>` の返信先の特定と、`>!reanchor <id>` の指定に使われます。`>#[` と `>#]` の片方を消してしまったときは、保存時に警告が出ます(他にスレッドがなく、返信先を決められないときはエラーです)。`>#` で始まる行は、保存時に無視されます。

コメントの位置で対象が決まります。

- 最初の `diff --git` より前: 差分全体へのコメント
- `+++` 行の後、最初の `@@` の前: ファイルへのコメント
- 差分の行の直後: その行へのコメント

書式を間違えて保存できなかったときは、内容が `<バンドル>.draft` に残ります。次の `edit` がそこから再開します。

## スナップショット

バンドルには、コメントが指す「ファイルの版」が保存されます。`edit --snapshot` で範囲を選べます。

- `changed`: 差分が触れたファイルの両側と、コメントが参照するファイル(git のレビューの既定)
- `full`: それに加えて head 全体(ディレクトリのレビューでは常にこちらで、`changed` の指定はエラー)

## コメントの位置について

コメントは「あるファイルの版の、この行範囲」という場所を覚えています。テキストは保存しません。差分が変わっても、記録された版どうしの行差分をたどって、論理的に位置を追います。似た行を探して当て推量することはしません。追いきれないときは、行が消えた位置を示して表示します。

## リリースの出し方

1. `Cargo.toml` の `version` を上げてコミットする。
2. `git tag v0.2.0 && git push origin main v0.2.0`(タグは `v` + `Cargo.toml` のバージョン)。
3. `.github/workflows/release.yml` が、各プラットフォーム向けにビルドして、Release を作る(`v0.2.0-rc1` のように `-` が付くタグは、プレリリース)。タグとバージョンが食い違うと、ビルドの最初で失敗する。

## ビルドとテスト

```sh
cargo test
```

統合テスト(`tests/cli.rs`)は、Linux と Windows のどちらでも動きます。エディタの代わりに、テストの実行ファイル自身を `$EDITOR` として再起動するので、シェルなどは要りません(git は要ります)。別の場所で作った実行ファイルを試すときは、環境変数 `DIFFNOTE_BIN` にそのパスを指定します。GitHub では、`.github/workflows/ci.yml` が、プッシュとプルリクエストごとに、Linux と Windows(最新の Rust)と、最低版の Rust 1.88(Linux)でテストし、最新の Rust では clippy の警告と、rustfmt の書式()もエラーとして扱います。コードを変えたら、 をかけてください。
